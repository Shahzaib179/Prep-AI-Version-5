# v4.9: tutor document library (one change only)

**Tutor Dashboard -> Create Quiz -> My own document** now works like the student *Personalized Learning* mode, but permanent.

## Pipeline (same building blocks as Personalized Learning)
| Step | What happens | Code |
|---|---|---|
| 1. Extract | PDF / DOCX / TXT / MD text, PDF page numbers kept | `documents.extract_document` (via `doc_quiz.prepare`, which also validates size, type, scanned/empty/protected files) |
| 2. Chunk | ~900-character sections, 150 overlap, each tagged with file + page | `documents.chunk_pages` |
| 3. Tokenise | lower-case keywords, stop words removed, light stemming (`enzymes` = `enzyme`); saved with each chunk | `tutor_docs.tokenize` |
| 4. Embed | `all-MiniLM-L6-v2` (free, open source), batches of 64 with a progress bar | `rag.embed_texts` |
| 5. Store | document row + one row per chunk (text, page, keywords, embedding) in `tutor_documents` / `tutor_doc_chunks` (migration 10) | `tutor_docs.ingest` |
| 6. Index | FAISS `IndexFlatIP` built from the stored vectors and cached per process; BM25 keyword index built from the stored tokens | `tutor_docs.load_store` |
| 7. Search | hybrid = 0.65 x meaning + 0.35 x BM25 keywords; or semantic only; or keyword only | `DocStore.search` |
| 8. Quiz | rounds of passages (whole document, or the chapter searched) -> MCQs, no repeats | `tutor_docs.plan_quiz` + `doc_quiz.generate` |

Why a database and not a `.faiss` file: Streamlit Cloud wipes local files on every restart. Vectors are stored as rows (like `memory_vectors`), so the document is processed **once**, survives restarts and works the same on SQLite and Supabase. The FAISS index is rebuilt in memory in well under a second.

## Using it
1. Pick **My own document**, upload up to 5 files, press **Process and save to library** (or just press **Generate Quiz**: unsaved files are processed first).
2. Choose which saved documents to use, pick a search method, optionally type a chapter or topic.
3. Open **Check what was extracted** to see sections, page numbers, keywords and a live search preview with scores.
4. **Generate Quiz**, then publish as usual.

## Rules
- Each tutor sees and deletes only their own documents. The same file uploaded twice by one tutor is recognised (SHA-256) and not processed again.
- Limits: 30 documents and 6000 sections per tutor, 5 files per upload, 15 MB per file, 700 sections per document.
- If the embedding model cannot load, nothing is half-saved; the message says to try again.
- Existing flows (knowledge-base quizzes, student Personalized Learning, PDF assignments) are unchanged.

## Deploy
Replace the files and restart. Migration 10 creates the two tables on start. For an existing SQLite-to-Supabase move, `scripts/migrate_sqlite_to_postgres.py` now copies these tables too.

## Tests
`python -m unittest tests.test_tutor_docs` (tokenising, BM25, ingest, metadata, restart without re-embedding, search modes, tutor isolation, bad files, limits, quiz plan) and `python tests/app_pages_smoke.py` (upload, progress, reuse, delete in the page). The sandbox has no FAISS wheel, so those tests exercise the identical numpy fallback; production uses `faiss-cpu` from `requirements.txt` (`Search engine: FAISS` is shown under the library table).

## v4.9.1 fix: `psycopg.errors.UndefinedColumn` on Tutor Dashboard -> My own document
Cause: migration 10 uses `CREATE TABLE IF NOT EXISTS`, so a `tutor_documents` table that already existed in Supabase with an older layout kept its old columns and `list_documents` failed.
Fix: migration 11 (`_m011_repair_tutor_documents`) checks every required column. Missing plain columns are added; a structurally different table is renamed to `<table>_legacy_<timestamp>` (nothing deleted) and recreated. Runs automatically on app start; re-upload your documents afterwards if the table was rebuilt.
